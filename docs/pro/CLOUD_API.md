# Lumen Cloud API (v1)

The REST API the mobile app (and, from P3, gateways) use. Machine-readable spec:
[openapi.json](openapi.json), generated by `cloud/tools/openapi.py` (CI checks that it is current). In
development the interactive docs are at `http://127.0.0.1:8800/api/v1/docs`; production does not serve them.

## Conventions

- Base path `/api/v1`, JSON in and out, camelCase field names, unknown fields rejected (400).
- Envelope on every response: `{"success": true, "data": …, "error": null}` or
  `{"success": false, "data": null, "error": {"code": "…", "message": "…"}}` — the same as the controller API.
- IDs are UUIDv7 strings. Times are ISO 8601 UTC.
- Request bodies are limited to 64 KB (413 `PAYLOAD_TOO_LARGE`).
- Error codes: `INVALID_REQUEST` 400, `WEAK_PASSWORD` 400, `CURRENT_PASSWORD_WRONG` 400, `INVALID_TOKEN` 400,
  `UNAUTHORIZED` 401, `INVALID_CREDENTIALS` 401, `INVALID_REFRESH_TOKEN` 401, `FORBIDDEN` 403, `NOT_FOUND` 404,
  `METHOD_NOT_ALLOWED` 405, `CONFLICT` 409, `EMAIL_IN_USE` 409, `CAPACITY` 409, `OWNER_MUST_TRANSFER` 409,
  `PAYLOAD_TOO_LARGE` 413, `ACCOUNT_LOCKED` 423, `RATE_LIMITED` 429 (with `Retry-After`), `INTERNAL_ERROR` 500,
  `UNAVAILABLE` 503.

## Authentication

| Item | Behaviour |
|---|---|
| Access token | JWT (HS256), 15 minutes, sent as `Authorization: Bearer <token>`. Claims `sub` (user), `sid` (session), `typ: access`, `iss: lumen-cloud`; header `kid` names the key so it can be rotated (`LUMEN_JWT_PREVIOUS_SECRET` keeps verifying old tokens). |
| Session | Every sign-in creates a session. Every request checks that the session is live and the account active, so sign-out, a password change or a revoked session takes effect at once, not when the token expires. |
| Refresh token | Opaque `lrt_…` (256-bit), 30 days, stored only as SHA-256. `POST /auth/refresh` returns a new pair and retires the old refresh token. Presenting a retired token again revokes the whole session (theft detection), so the app must refresh **single-flight**. |
| Passwords | argon2id (64 MiB, t=3, p=4). 10–128 characters, not the e-mail or based on it, at least 4 different characters. |
| Sign-in limits | 5 failures per IP + e-mail and 30 per IP per 5 minutes (429); 10 consecutive failures lock the account for 5 minutes (423). Unknown e-mail and wrong password give the same 401 and take the same time. |
| Registration | 10 per IP per hour. A duplicate e-mail is 409 `EMAIL_IN_USE`. Sign-in works before the e-mail is verified; claiming devices will require it (P11). |
| Password change | Needs the current password; signs out every other session. |
| Reset | `POST /auth/password-reset/request` always answers 202 (no account enumeration; at most 3 e-mails per IP + address per hour). The `lpr_…` token lasts 30 minutes, is single use, and the newest one invalidates older ones. Confirming signs out every session and clears a lockout. |
| E-mail verification | `lev_…` token, 2 days, single use. E-mail delivery is a development log sender until P10. |

## Homes and roles

A home has exactly one owner; ownership moves only with `POST /homes/{id}/transfer` (the old owner becomes admin).
A home the caller is not a member of returns **404**, never 403.

| Action | owner | admin | member | guest |
|---|---|---|---|---|
| View home, rooms | ✓ | ✓ | ✓ | ✓ |
| Control lights and scenes (P4) | ✓ | ✓ | ✓ | ✓ |
| View members | ✓ | ✓ | ✓ | |
| Rename home, change time zone | ✓ | ✓ | | |
| Create, rename, delete rooms | ✓ | ✓ | | |
| Change roles, remove members (lower role than yours only) | ✓ | ✓ | | |
| Manage devices (P3) | ✓ | ✓ | | |
| Delete home, transfer ownership | ✓ | | | |

Anyone can leave a home (`DELETE /homes/{id}/members/{their own id}`) except the owner (409
`OWNER_MUST_TRANSFER`). Limits: 20 homes per account, 100 rooms per home; room names are unique per home.
Members join through invitations (P10).

## Devices, claims and local tickets (P3)

Gateways and controllers are both "devices" of a home. Controllers reach the cloud only through their gateway
(DECISIONS D-17). Registration details, the setup code and re-pairing are in PROTOCOL.md §8.

| Step | Who | Call |
|---|---|---|
| Add a gateway | app (owner/admin) | `POST /homes/{id}/gateway-claims {setupProofHash}` → `claimToken` (15 min, single use); the gateway then calls `POST /gateway/register` with the token and its setup code and receives its broker credential |
| Add a controller | app (owner/admin) | `POST /homes/{id}/claims {gatewayId}` → `claimToken`; the controller passes it to its gateway, which calls `POST /gateways/{id}/children/register` (Basic auth) and hands `K_local` to the controller |
| Rename, set room | owner/admin | `PATCH /devices/{id} {name?, roomId?}` (`roomId: null` clears it) |
| Remove | owner/admin | `DELETE /devices/{id}`: a gateway loses its credential and is disconnected from the broker; its controllers stay in the home, unassigned |
| Local access | any member | `POST /devices/{id}/local-ticket {scope}` → `{ticket, expiresAt, lan:{controllerId, url}}`. `control` (7 days) for every role; `admin` (12 h) for owner/admin only |

Limits: 64 devices per home; 20 device registrations per IP per hour. A claim made for one gateway cannot be
redeemed by another (403, and the claim stays usable for the right gateway).
