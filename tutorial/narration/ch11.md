# ch11

The Network page covers how the controller connects, and the security model behind it.

Wi-Fi is set with a network name and a password. The password is write-only, just like the MQTT password. You can also give the controller a static IP address.

The setup hotspot has four modes: Wi-Fi with the hotspot only when Wi-Fi is unreachable, which is the default, Wi-Fi only, both together, or the hotspot alone. It is always protected with WPA2, and there is never an open management hotspot.

Boards with an Ethernet port, such as the KC868-AP, can use a wired connection instead.

Every controller has a hostname, and it announces itself with mDNS, so you can reach it by name on your local network. The time zone setting is used by schedules and sun times.

Now the security model, in one place.

The default password must be changed on first sign-in. Passwords are stored as salted PBKDF2 hashes. Sessions use a cookie the browser scripts cannot read, plus a token that protects every change against cross-site requests.

Sign-in attempts are rate limited per address, and repeated failures lock the account for a few minutes.

Secrets, such as passwords, MQTT credentials and network keys, live only in NVS. They are never written to configuration files, backups, exports or logs.

Every control path is authenticated: the web app, the WebSocket, TCP with its token, signed UDP, and ESP-NOW with its network key.

And the web app itself loads nothing from the internet. No fonts, no scripts and no tracking. It works fully offline.
